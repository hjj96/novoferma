# Работа над сайтом Новофермы

Актуальный сайт находится в `output/concept/`. Генератор страниц —
`scripts/build_site.py`, данные и готовая графика — в `output/concept/`.
Не запускай генератор поверх прямых правок HTML, если они ещё не перенесены
в его исходники. Не меняй дизайн или содержание ради публикации.

## Автоматическое обновление командной версии

Пользователь разрешил автоматически обновлять тестовый сайт **после каждой
завершённой правки сайта**. Это правило действует и в следующих чатах проекта.
Публикуй готовый результат без дополнительного запроса подтверждения, если
пользователь явно не попросил оставить изменения локально или не публиковать.
Обычные ответы, исследование, работа над отдельными PDF/презентациями и изменения
документации без изменений сайта не требуют публикации.

Постоянная ссылка: **https://novoferma-team-preview.vercel.app/**.
Используй существующий проект Vercel и его команду из
`output/hosting/deployment.json`. Это отдельный проект командного тестирования;
его постоянный адрес обслуживает окружение `production`.

После реализации правки и необходимых проверок:

1. Запусти `python3 scripts/publish_team_preview.py` из корня проекта.
   Скрипт проверяет страницы и поведение, создаёт проверенный пакет, обновляет
   отдельный снимок сайта и отправляет его в предназначенную для хостинга ветку.
   Основная рабочая ветка и её незакоммиченные изменения остаются на месте.
2. Прочитай итоговый JSON скрипта или `output/hosting/pending-publish.json`.
   Если `deploymentRequired` равно `false`, версия уже опубликована и повторять
   публикацию не нужно. В остальных случаях передай выведенные аргументы
   **без изменения commit SHA** подключённому
   инструменту Vercel `create_deployment`. Если нужный коммит уже публикуется,
   продолжи существующую публикацию вместо создания дубликата.
3. Сразу сохрани возвращённые `deploymentId` и `deploymentUrl` в существующий
   `output/hosting/pending-publish.json`, сохранив остальные поля. Дождись `READY`
   через `get_deployment`. Для ошибки прочитай build logs,
   исправь причину в пределах задачи и повтори подготовку при изменении файлов.
4. Заверши публикацию командой
   `python3 scripts/publish_team_preview.py --finalize DEPLOYMENT_ID --deployment-url https://DEPLOYMENT_HOST`.
   Скрипт проверит метку версии на постоянном адресе и запрет индексации,
   затем запишет сведения об успешном обновлении.
5. Сообщай об обновлении сайта только после этих проверок. Если публикация
   недоступна, явно сообщи, что по ссылке осталась предыдущая версия, и сохрани
   подготовленный снимок для продолжения. Не называй подготовку успешным деплоем.

Необходимые инструменты Vercel доступны через каталог `ALL_TOOLS`.
Перед работой с Vercel прочитай доступный skill `vercel:deployments-cicd`.
Доступ через уже подключённый инструмент не требует входа в браузере или
копирования токенов. Не сохраняй секреты в репозитории или аргументах команд.

Не устанавливай фоновый watcher и не публикуй промежуточные сохранения файлов.
Публикация запускается агентом в конце завершённой правки, а не на каждый ввод.
Существующее согласие пользователя покрывает эту публикацию.

Не переключай основную рабочую ветку, не делай `git add .` в корне, не отправляй
исследования и PNG-мастера на хостинг, не используй force push. Публикуются только
файлы, выбранные `scripts/package_site.py`, служебная метка версии и настройки
временного хостинга. Сохраняй `noindex` и запрещающий `robots.txt`.
