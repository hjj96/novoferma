# Страница партнёров: причины типографических проблем

4 ноября 2026. Read-only анализ текущих `scripts/build_site.py`, `output/concept/partners.html`, `partners-scenes.css` и общих стилей. Headless-браузер и проверки формы в этом проходе не запускались. Просмотрены свежие снимки `390.png` и `1440.png`, снятые основным исполнителем в in-app browser.

1. **Сближение соседних букв задаёт отрицательный tracking.** Для всех заголовков страницы установлено `letter-spacing:-.012em`. Файл `RobotoFlex-Protein.woff2` — статический Novoferma Protein ExtraBold Condensed, weight 850, unitsPerEm 2048; переменных осей нет. У «К» advance 1186, правый край контура 1199; у «У» левый край −19. С учётом tracking их bounding boxes перекрываются на 56,576 единицы шрифта: около 1,52 px при размере 55 px и 3,58 px при 129,6 px. Отдельная растровая проверка контуров через FreeType при 1024 px/em подтвердила пересечение «КУ» при −.012em; при tracking 0 пересечения нет. Это причина начать с `letter-spacing:0`, затем проверить размер строки; один `line-height` соседние буквы не раздвинет.

2. **H1 тесный по вертикали, но расчёт не подтверждает столкновения двух его строк.** Сейчас line-height .85 на desktop / .88 на mobile; между block-span добавлено 10 / 5 px. С учётом реальных контуров «ДЕЛО» и «СО ВКУСОМ.» расчётный промежуток составляет около 8,8 px при 129,6 px и 6,2 px при 57,72 px. Вертикальную тесноту можно ослабить до .94–1, однако она не объясняет контакт букв внутри слова. У H1 и его spans нет `overflow:hidden`; общий `#main` имеет `overflow-x:clip`, поэтому горизонтальное выпирание может скрываться, даже если документ не скроллится.

3. **Тонкость информационного текста заложена каскадом.** `font-face.css` задаёт переменный Onest как Novoferma Sans (100–900); по умолчанию body наследует weight 400. Описания предложений 16 px / 15 px mobile и текст контактов не получают собственного веса; labels и опции формы — 12 px / 500, вспомогательный текст — 12 px / 400. `polish.css` добавляет `-webkit-font-smoothing:antialiased`. На фоне очень плотного Protein850 такой текст выглядит лёгким. Точечная отправная точка: local body 450–500, labels/actions 600, вторичный текст 13 px; выбирать по свежему рендеру.

4. **Просто повысить `font-weight` H1 недостаточно.** У Protein объявлено единственное статическое начертание 850, а корневой стиль задаёт `font-synthesis:none`. Значение 900 само по себе не создаст более плотного контура. Если на снимке заголовок выглядит тонким, сначала проверить загрузку файла и фактически выбранный font-face; статический файл уже ExtraBold. В просмотренных снимках рисунок соответствует плотной Protein, поэтому видимой причиной тонкости здесь является прежде всего body/UI.

5. **Слабее читается мелкий текст на оранжевом.** Hero description и eyebrow используют `#402111` на `#fa4b06`; расчёт контраста по CSS-цветам — 4,21:1. Уже существующий `--ink:#301709` даст 4,85:1. Кремовый H1 на оранжевом имеет 3,20:1 и остаётся большим жирным текстом. Подписи формы на коричневом имеют существенно больший контраст; там первична величина и насыщенность шрифта.

6. **На узком mobile ломается ритм предложения СТМ.** В mobile CSS H2 имеет нижнюю границу 49 px, а «НАШ ПРОДУКТ.» при текущем tracking требует примерно 307 px при доступных 288 px на ширине 320. Поэтому строка может разбиваться дополнительно после «НАШ», тогда как соседнее предложение сохраняет две строки. Для общей сетки нужен управляемый размер по доступной ширине; добавление `white-space:nowrap` без уменьшения размера создаст выпирание.

7. **Мобильный hero собирается из разнесённых grid-элементов.** `display:contents` разносит h1, описание и CTA по grid-ячейкам; персонажу выделена отдельная колонка и фиксированная высота 225 px (195 px до 359). На свежем 390 px описание занимает узкий левый столбец и начинается существенно ниже заголовка, CTA — отдельной широкой строкой под рисунком. Это объясняет ощущение разрозненности; точечное решение — связать h1 и lead одной вертикальной группой и сократить лишний промежуток, сохранив отдельное место для полного персонажа.

Ограничения: значения font metrics получены из локального файла; ширины строк рассчитаны HarfBuzz/FontTools, пересечение пары проверено FreeType/Pillow. Это не замена измерениям фактического DOM, проверке выбранного font-face и свежему визуальному контролю после исправлений. Положительное пересечение bounding boxes само по себе не считалось пересечением контуров. Продуктовые файлы не изменены.
